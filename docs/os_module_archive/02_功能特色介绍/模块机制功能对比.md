## 2. 持久化机制对比

### 2.1 空闲页持久化

| 方案 | 描述 | 优点 | 缺点 | 选择 |
|---|---|---|---|---|
| **A** | `<db>.fpl` 24B header（magic=0x46504C31/version=1/pages/size）+ 位图；惰性创建（首次 `DeallocatePage`）；位图 bit 与 next_page_id_ 双校验 | 不改数据格式；CRC 损坏数据安全优先（`.fpl` 校验失败则丢弃位图，不破坏数据）；可按需创建 | 需新建文件、需加载时校验 | ✅ 当前 |
| B1 | 在数据文件每页 header 嵌 is_free 标志位 | 单一文件 | 改页格式（破坏兼容）；CRC 不一致即拒绝恢复 | ❌ |
| B2 | 维护空闲页链表（首页指针嵌入表首页） | 零额外文件 | 链表腐烂风险（异常断链）；重启需全表扫描重建 | ❌ |
| B3 | WAL 记录 free 操作 | 复用 WAL | 启动扫描 WAL 太慢；占用日志空间 | ❌ |

### 2.2 页 CRC 损坏检测

| 方案 | 描述 | 优点 | 缺点 | 选择 |
|---|---|---|---|---|
| **A** | `<db>.crc` headerless 4-byte u32 CRC32 per page（IEEE 0xEDB88320，const-expr 表 0 初始化）；`\analyze` 统计损坏数；Sync() 顺序先 .crc 后 data | 不改数据格式；崩溃保护（先 .crc 防止未校验前误读） | 额外文件 | ✅ 当前 |
| B1 | 每页 header 内嵌 CRC | 单文件 | 改页格式；CPU 校验阻塞热路径 | ❌ |
| B2 | 块设备校验和 | 介质级 | 抽象层依赖外部能力 | ❌ |
| B3 | 不做检测 | 性能最优 | 静默损坏 | ❌ |

### 2.3 持久 fsync

| 方案 | 描述 | 选择 |
|---|---|---|
| **A** | Windows `_commit(_fileno(f))` 真持久 fsync | ✅ |
| B | 关闭文件即视为持久 | ❌（数据丢失） |

### 2.4 WAL 组提交时间窗

| 窗口值 | 实测 fsync 次数 | 备注 |
|---|---|---|
| 0ms | 1314 | 基线（纯 follower） |
| 1ms | — | — |
| 2ms | 1100 | -16% |
| 5ms | — | — |
| **10ms** | **1089** | **推荐（-17%，膝点）** |

## 3. 缓存与替换策略对比

| 策略 | 命中路径 | 实现复杂度 | 适用场景 | 选择 |
|---|---|---|---|---|
| **LRU** | 双向链表 + 哈希位置表 | 中 | 通用 | ✅ 默认 |
| **FIFO** | 队列 | 低 | 顺序流 | ✅ 可配 |
| **CLOCK** | 环形 + 二指 second-chance | 低 | 近似 LRU、低开销 | ✅ 可配 |
| **LRU-K（K=2）** | recent_store_<K + historic_store_≥K | 高 | 抗扫描、稀疏访问 | ✅ 可配 |
| 随机 | — | — | 学术 | ❌ |

**温度感知刷盘**：P 百分位脏页访问计数 = hot_ratio_% × n（默认 20%）→ 自适应阈值；flat-distribution guard（range<2 → all cold）+ boundary-tier cap guard；LRU-K 地板为 K；`SetHotAccessThreshold` 关闭自适应。

## 4. 并发控制机制对比

### 4.1 行锁

| 维度 | 全局 mutex 串行 | 16 shard（splitmix64） + table_hint≥0 跳 meta_mutex | 选择 |
|---|---|---|---|
| 异表吞吐 | 5.8× 基线 | 5.8× 实测 | ✅ 当前 |
| 同表冲突 | 正常 | 正常 | ✅ |
| 热点表 | 串行化 | 单 shard 串行 | ✅ |
| 复杂度 | 低 | 中（行锁分片计数需在 shard 内） | ✅ |

### 4.2 B+Tree 并发

| 方案 | 描述 | 吞吐 | 选择 |
|---|---|---|---|
| **A 乐观页级** | 页级读写闩 + 乐观重启（版本校验）+ 慢路径写闩下降 + 先 pin 后加闩 | 3.18×（16 线程） | ✅ |
| 树级粗锁 | 整树 mutex | 1× | ❌（基线对照） |
| Blink-Tree | 节点链接不分裂 | 高 | ❌（实现复杂） |
| 物理版本链 | 每页保留版本 | O(1) | ❌（开销大） |

### 4.3 隔离级别

| 级别 | 读锁释放点 | 一致性 | 性能 | 选择 |
|---|---|---|---|---|
| **READ COMMITTED** | 语句结束（success/exception） | 单语句 | 高 | ✅ |
| REPEATABLE READ | 事务结束 | 语句间一致 | 中 | ✅ |
| **SERIALIZABLE** | 事务结束 | 全序 | 低 | ✅ |
| **SNAPSHOT** | 事务结束 + 版本链可见性 | MVCC | 中 | ✅ |

**SNAPSHOT 必要条件**：事务挂载必须在读行循环前，否则 `RecordSnapshotRead` 捕获的快照基数错误（FCW 失效）。

### 4.4 谓词锁

| 方案 | 描述 | 复杂度 | 性能 | 选择 |
|---|---|---|---|---|
| **A 区间树** | (表, 列, lo, hi) 区间注册；中心区间树 O(log P + K) | 中 | O(log P + K) | ✅ |
| 哈希集合 | (表, 列, 键) 点集 | 低 | O(1) 点冲突，但范围无 | ❌（不覆盖范围） |
| 全表扫描 | O(谓词数 × 行数) | 低 | 不可用 | ❌ |

**复合索引最左前缀**：`CompareKeyPrefix` 决定 lo/hi 边界；非最左列上的谓词不参与范围收敛（需 index merge 配合，本次未启用）。

## 5. 恢复机制对比

| 方案 | 描述 | 选择 |
|---|---|---|
| **A WAL-before-data + redo/undo + CLR** | 提交前 fsync 日志；数据页可迟到；abort 用 CLR 链支持中断后继续回滚 | ✅ |
| Shadow paging | 每事务 copy-on-write | ❌（空间爆炸） |
| 只 redo | 无 undo | ❌（不支持 rollback） |

**关键不变量**：崩溃恢复 49/50 两阶段；`.crc` 必须先 `.data` 同步。

## 6. 查询优化机制对比

### 6.1 JOIN 顺序

| 方案 | 描述 | 选择 |
|---|---|---|
| **A 启发式重排** | 全 INNER 左深链 + 估计基数小表驱动 + 就近贪心（避免笛卡尔积）；OUTER/未限定列/无法归属守底 | ✅（U3-1） |
| System R 动态规划 | 全局最优 | ❌（复杂度高，本次不实现） |
| Volcano 迭代 | 自底向上代价 | ❌（同上） |

**守底**：仅全 INNER 重排，LEFT/RIGHT/FULL/未限定列/无法归属/探针失败保持原序。

### 6.2 聚合下推

| 方案 | 描述 | 选择 |
|---|---|---|
| **A 聚合下推（PreAggScan）** | IsPreAggEligible 三重守底（单表/裸聚合/无嵌套聚合）；扫描循环内累计 AggState；unordered_map 哈希分组 O(1) | ✅（U3-2） |
| 不下推 | 全量扫描 + 内存分组 | ❌（基线对照） |
| 部分下推 | 简单 COUNT/MAX/MIN 下推，SUM/AVG 不下推 | ❌（实现复杂） |

**语义对齐**：COUNT(*) 计行/COUNT(col) 非 NULL/SUM 仅数值累加且空输出 NULL/无 GROUP BY 空输入仍发射初始状态行。

### 6.3 子查询处理

| 方案 | 描述 | 选择 |
|---|---|---|
| **A 去关联** | DecorrelateSubqueries：相关 EXISTS/NOT EXISTS/IN/ANY → SEMI/ANTI JOIN（JoinType::SEMI/ANTI）；非相关物化缓存 + 递归 CTE 边界失效 | ✅（U3-3） |
| 不去关联（row-by-row） | 相关子查询逐行求值 | ❌（O(n²) 复杂度） |
| 子查询转 CTE | 仅语法改写 | ❌（未做去关联） |

**形态守底**：内层单表、无 GROUP BY/HAVING/ORDER BY/DISTINCT/LIMIT/派生表/JOIN；IN/ANY 要求 select_list 单裸列。
**保守守底**：NOT IN/NOT ANY（NULL 三值）、相关合取项含嵌套子查询/未限定列、CondRefsResolve 无法解析——任一不过保持原 Filter 零回归。

## 7. 性能评估汇总

| 指标 | 基线 | 当前 | 加速比 | 来源 |
|---|---|---|---|---|
| 快照水位读取 | O(n) | O(1) | ~465× | T3 |
| WAL 组提交 fsync | 1314 | 1089 | 9.8×~10.7× | U2-3 |
| B+Tree 并发写（16 线程） | 1× | 3.18× | 3.18× | Phase 1 |
| 分片锁异表（5.8×） | 全局串行 | 16 shard | 5.8× | Phase 5 |
| 乐观校验（U1d） | O(树高) | O(1) | 与树高相关 | U1d |
| 单元测试基线 | 0 | 292643 | n/a | T5 → U3-3 |
| SQL 回归 | 0 | 56 | n/a | U3-3 |
| 崩溃注入 | — | 49/50 | n/a | T2+ |

**Staged OS 优化基准（`OsModuleOptimizations`）**：
- CRC 吞吐：优化 261.1 MB/s vs 基线 263.8 MB/s（一致 PASS）
- LRU 吞吐：优化 2.2 M ops/s vs 基线 2.0 M ops/s（加速 1.08×）
- 分配遍历：优化 64 次/次 vs 基线 128 次/次（减少 50%）
