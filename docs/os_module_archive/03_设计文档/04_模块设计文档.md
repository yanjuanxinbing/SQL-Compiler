## 1. 模块定位与总体架构

### 1.1 模块职责

本模块是数据库系统的**物理存储底座**，向上层（存储引擎、索引、系统目录、事务恢复、执行引擎）提供以「页」为单位的缓冲区管理与磁盘访问接口。指导书要求的核心能力：

1. **页式存储模型**：固定 4KB 页、唯一页号、页的分配/释放/读写；
2. **缓存管理与替换策略**：LRU / FIFO 可替换、命中统计、替换日志输出；
3. **统一存储访问接口**：供数据库模块调用，并与执行计划对接。

### 1.2 分层架构

模块采用四层结构，依赖方向严格单向（上层依赖下层，下层不感知上层）：

```text
┌──────────────────────────────────────────────────────────┐
│ 上层消费者：TableHeap · BPlusTree · SystemCatalog ·        │
│           Recovery · 各执行器（SeqScan/IndexScan/写算子）   │
└───────────────────────────┬──────────────────────────────┘
                            │ get_page / new_page / unpin / flush_pages
┌───────────────────────────▼──────────────────────────────┐
│ 第 3 层 缓存管理 BufferPoolManager                         │
│  帧数组 + 页表哈希 · pin 计数 · 脏标记 · 命中统计 · 替换日志 │
│  WAL-before-data 判定 · 温度感知刷脏 · 后台刷脏 · 组提交    │
└───────────────────────────┬──────────────────────────────┘
                            │ 调用 Replacer（策略模式）
┌───────────────────────────▼──────────────────────────────┐
│ 第 2 层 替换策略 Replacer 接口族                           │
│  LRU / FIFO / CLOCK / LRU-K（接口可插拔）                 │
└───────────────────────────┬──────────────────────────────┘
                            │ read/write/allocate/deallocate
┌───────────────────────────▼──────────────────────────────┐
│ 第 1 层 物理磁盘 DiskManager + BlockDevice                 │
│  页偏移定位 · 读写 · 真持久 fsync · .fpl 空闲页位图 ·       │
│  .crc 页校验 · 块设备抽象（故障注入）                      │
└───────────────────────────┬──────────────────────────────┘
┌───────────────────────────▼──────────────────────────────┐
│ 第 0 层 物理介质：数据文件（页 = PAGE_SIZE=4KB 块）          │
└──────────────────────────────────────────────────────────┘
```

并行横切层：**事务子系统**（LogManager / RecoveryManager / TransactionManager / LockManager / CommitTracker）与 **索引层**（BPlusTree 页级并发）。

### 1.3 关键数据结构

| 结构 | 用途 |
|---|---|
| `Page` | 内存页帧：4KB 数据 + page_id + is_dirty + pin_count + page_lsn + 帧级读写闩 + 原子访问计数 |
| `page_table_` | page_id → frame_id 哈希（命中判定） |
| `BufferPoolStats` | 命中/缺失/替换计数 + 写回统计（温度分档）+ IO 计数 |
| `ReplacementLogEntry` | 单条替换日志 `{evicted, loaded, evicted_was_dirty}` |
| `MvccRecordHeader` | 48B 版本头（begin/end_xid、begin/end_csn、prev_page/slot） |
| `IntervalNode` / `PredicateTable` | 谓词锁按表组织的居中区间树 |
| `CommitTracker` | 共享提交追踪：快照登记、低水位 O(1) 缓存 |

## 2. 核心机制与实现原理

### 2.1 页式存储模型（DiskManager + Page）

**原理**：文件按固定 4KB 页组织，页号 × PAGE_SIZE 得文件偏移。`AllocatePage` 优先复用空闲页、否则递增 `next_page_id_`（由文件大小推导）；`DeallocatePage` 将页号写入空闲列表。`ReadPage/WritePage` 走块设备层，`Sync` 经平台分支实现真持久（Windows `_commit(_fileno)` / POSIX `fsync`）。

**关键设计**：
- **空闲页跨重启持久化（`.fpl` 旁路位图）**：24 字节头（magic/version/pages/size）+ 位图（位 i=1 ⇒ 页 i 空闲）。惰性创建（首次 Deallocate 才落盘），装载时校验「页数 == 由文件大小推导的 next_page_id_」，不符即安全丢弃（数据安全优先于空间复用）。复用前先清位并持久化，杜绝崩溃后双重分配。
- **页 CRC 损坏检测（`.crc` 旁路）**：无头，每页 4 字节 u32 CRC32；无记录视为旧库跳过校验；写路径记录、读路径核对、回收清除。与 BlockDevice 故障注入联动，拦截坏块。
- **64 位文件定位**：`_fseeki64/_ftelli64`（Windows）、`fseeko/ftello`（POSIX），支持 >2GB 文件。

**设计原因**：选择旁路文件而非「页头/独立 meta 文件」——避免改数据文件布局（高迁移风险）、避免双文件崩溃不一致；`.fpl`/`.crc` 均向后兼容，旧库行为逐字节不变。

### 2.2 缓存管理（BufferPoolManager）

**原理**：`GetPage` 命中走页表；未命中经 `FindFreeFrame`（优先空闲帧、否则替换器淘汰）从磁盘加载。`UnpinPage` pin 归零后交还替换器。淘汰脏页前先按 WAL 规则刷日志再写盘（**WAL-before-data**）。

**关键设计**：
- **替换策略族（策略模式）**：`Replacer` 虚接口隔离算法与缓冲池本体。LRU（双链表+定位器 O(1)）、FIFO（队列+集合延迟删除）、CLOCK（环形指针+参考位二次机会）、LRU-K（双集合结构，K=1 退化为 LRU）。满足指导书「可配置、可统计、可输出日志」。
- **命中统计与替换日志**：`BufferPoolStats` 实时维护；`ReplacementLogEntry` 环形上限 1024 条；`\stats` 命令输出命中率、替换日志、IO 计数、内存占用、后台刷脏状态。
- **WAL 组提交（提交路径）**：批量取脏页最大 page_lsn，一次刷日志 + 一次 Sync，COMMIT 系统调用成本从 O(脏页数) 收敛到 O(1)。
- **温度感知刷盘**：`Page::access_count_` 原子采集热度，`FlushAllDirtyPages` 只写回冷脏页、热页留池（NO-FORCE + WAL-before-data 保证崩溃后可恢复），削减写 IO 并保留热页命中率。
- **后台刷脏**：可选后台线程周期刷脏（环境变量 `SQLCOMPILER_BG_FLUSH_MS`，默认关闭），仅写 OS 缓存不调 Sync，不改变组提交 fsync 次数。
- **内存上限可配置**：环境变量 `SQLCOMPILER_BUFFER_MEMORY`（字节）换算帧数，`\stats` 输出已用/上限。
- **页级读写闩**：帧内 `std::shared_mutex`，RAII `PageReadGuard`/`PageWriteGuard`；所有写回路径落盘前取页读锁防写盘撕裂；持页闩期间绝不请求全局 `latch_`（锁序无环）。

### 2.3 事务、锁与隔离级别（LockManager + TransactionManager）

**原理**：LockManager 管理 S/X 锁（行级 + 表级多粒度）、谓词锁；等待图 DFS 死锁检测；`UnlockAll` 按事务整体释放。事务按隔离级别持有锁：
- **READ UNCOMMITTED**：不取读锁；
- **READ COMMITTED**：读锁语句末释放（成功/异常路径均释放，防泄漏），写锁持有到提交；
- **SERIALIZABLE**：读锁/写锁持有到提交 + 谓词锁防幻读；
- **SNAPSHOT（MVCC）**：读者免读锁，写者行 X 锁 + 提交期 first-committer-wins。

**关键设计**：
- **行级锁**：`RowResourceId` 用符号位标记行锁命名空间，与表锁（非负页号）不相交；
- **谓词锁区间树**：按表组织的居中区间树（分裂点=lo 中位数），写前检查 O(log P + K)，全表谓词作全域哨兵，惰性重建摊薄更新成本；
- **自适应锁升级**：按「已登记行锁数 × 表规模 + 冲突采样」动态调整升级阈值，小表提前升级、大表延后；
- **死锁检测**：等待图 DFS，检测到环即返回 kDeadlock 并中止 victim；victim 撤销自身等待边避免残留；
- **MVCC 快照**：CommitTracker 维护全局 CSN 分配与活动快照；版本链 48B 头 + prev 指针；`SetSnapshot(csn, tracker)` 启用可见性过滤；FCW 在提交期比对快照读基，输家中止。

### 2.4 日志与崩溃恢复（LogManager + RecoveryManager）

**原理**：WAL-before-data —— 数据页落盘前确保其 page_lsn 之前的日志已持久化。日志记录含 LSN、事务 id、页号、before/after image。恢复分两阶段：redo（重放已提交变更）+ undo（回滚未提交变更），CLR 链支持中途崩溃的持续回滚。

**关键设计**：
- **组提交领导者-跟随者**：并发提交共享一次 fsync（128 并发提交仅 12 次 fsync，10.7× 削减）；
- **CRC 旁路 + 崩溃注入测试**：49_acid_recovery（未提交回滚/已提交持久）、50_undo_clr（CLR 链补做）两套跨重启验证。

### 2.5 B+Tree 乐观页级并发（OS 优化 Phase 1，创新特性 A）

**原理**：树级粗粒度锁升级为**页级读写闩 + 乐观重启**：
- 页头 offset 12 保留字段复用为单调**版本号**（不改页格式），内容每次改写自增发布；
- **乐观只读下降**：逐页取共享闩记录 (pid, version) 路径快照，`ValidatePath` 复核未变则通过，任一变化整体重启（上限 256 次兜底）——读不阻塞写、无锁等待、无等待环；
- **写路径分档**：快路径（叶放得下）乐观下降后只对目标叶取独占写闩；慢路径带写闩下降 + 预分裂保证叶一定放得下；
- **分裂并发安全**：`SplitChild/SplitRoot`「先 pin 后加闩」同时持多把写闩而不违反锁序；加闩后复读内容，检测结构被并发改写则释放并返回重启信号；
- **游标**：「物化快照 + 版本校验 + 重定位」，跨叶前进校验版本，保证不跳过/不重复条目。
- **实测**：4 线程 1.93× / 8 线程 2.71× / 16 线程 3.18×（vs 树级锁基线）。

### 2.6 MVCC 优化族（Phase 2 / Phase 3 / Phase 4）

| 机制 | 阶段 | 原理 |
|---|---|---|
| **O(1) 快照低水位** | Phase 2 | CommitTracker 维护单调 `low_water_mark_`（= 活动快照最小 CSN），事件驱动缓存，脏时惰性重算；1 万快照下读取 ≈14ns/次（约 500× 提速） |
| **内联轻量真空** | Phase 2 | 写路径持页写锁时顺带回收 end_csn ≤ 低水位的旧版本槽位（每语句 k=8 预算），后台真空降为低频兜底；滞后 91.7% ↓ |
| **版本链 O(1) 查询** | Phase 3 | TableHeap 内存版本索引缓存（rid→按 begin_csn 排序版本数组，5 元组头槽标记校验），纯内存不改磁盘格式 |
| **索引墓碑回收** | Phase 3 | `DecideIndexEntry`（页读锁 + 槽头检查 + 键比较 + 活动快照可见区间判定）+ `BPlusTree::Vacuum` 物理删除 |
| **自适应锁升级** | Phase 3 | 数据驱动阈值（表规模 × 行锁数 + 冲突采样） |
| **谓词锁区间树** | Phase 4 | O(P) → O(log P + K) 点查询 |
| **WAL 组提交** | Phase 4 | 领导者-跟随者批量 fsync，10.7× I/O 削减 |
| **温度感知刷盘** | Phase 4 | 冷热分级写回，热页留池 |

## 3. 数据流程

### 3.1 写路径（INSERT）
```text
Parser → Planner → InsertExecutor
  → AcquireRowWriteLock（LockManager，SNAPSHOT 下 + FCW 登记）
  → TableHeap::InsertTuple（per-table write_mutex_ 串行化整段写序列）
      → GetTuple 版本可见性（SetSnapshot 后）
      → 写新版本/覆写 head（页写闩内，记 page_lsn）
  → IndexMaintenance（B+Tree 页级闩插入）
  → 页标记脏 → 提交时 GroupCommit 刷 WAL → （可选）温度感知刷盘
```

### 3.2 读路径（SELECT + 快照）
```text
SeqScan/IndexScanExecutor::Init → SetSnapshot(csn, tracker)
  → 遍历页（PageReadGuard）→ GetTuple 沿版本链 VisibleForSnapshot 过滤
  → IndexScan 回表 RID 去重 + 可见版本键重检（InScanBounds）
  → RC 语句末 / SERIALIZABLE 提交时 UnlockAll 释放读锁
```

### 3.3 崩溃恢复路径
```text
启动 → DiskManager 装载（.fpl/.crc 校验）→ RecoveryManager
  → 分析 WAL 构建重做/撤销集合 → redo 已提交变更 → undo 未提交变更（CLR 链）
  → 数据文件 + WAL 达到一致状态
```

## 4. 关键技术点

1. **WAL-before-data 一体化缓冲池**：FlushPage 写盘前检查 `page_lsn > durable_lsn`，从机制上避免「磁盘页领先 WAL」导致 redo 失效。
2. **RAII 页句柄（PageGuard）**：把 GetPage/UnpinPage 的成对遗漏移植到编译期，消除 pin 泄漏。
3. **锁序不变量**：`BPM::latch_ → LogManager::mutex_`、`BPM::latch_ → DiskManager::db_io_latch_`；持页闩不请求 BPM；组提交只在 `mutex_`/`gc_cv_` 等待。
4. **乐观重启 vs 等待**：B+Tree 读路径无锁等待（版本校验失败即重启），与 DFS 死锁检测正交。
5. **零磁盘格式变更**：版本号用页头保留字段；`.fpl`/`.crc`/WAL/48B 版本头布局不变，向后兼容。
6. **确定性并发正确性**：per-table write_mutex_ 串行化跨多次缓冲池访问的 check-then-act 写序列（找页→判满→新建→链接→插入），杜绝链表分叉丢行。

## 5. 设计决策依据（代表性）

| 决策 | 依据 |
|---|---|
| 旁路 `.fpl`/`.crc` 而非改数据文件 | 零迁移风险、旧库逐字节兼容；数据安全优先 |
| Windows `_commit` / POSIX `fsync` 而非 fstream::sync | MSVC fstream::sync 仅到 OS 缓冲，非真持久 |
| 策略模式替换器 | 新增算法零侵入缓冲池；满足「可配置/可统计/可输出」 |
| 乐观页级并发而非朴素 crabbing | 无锁等待环、读写不互斥；与死锁检测正交 |
| 组提交 + 温度感知刷盘 | COMMIT 吞吐不受磁盘 IOPS 上限；NO-FORCE+WAL 保证恢复正确 |
| SNAPSHOT 免读锁 + FCW | 读者永不阻塞、写者串行；丢失更新被提交期裁决拦截 |
| 磁盘格式零变更 | 版本链/版本号/统计均为进程内内存态，落盘语义不变 |

## 7. 并发模型（T5 收口补录）

本模块的并发正确性由「**四层锁层次 + 严格锁序 + 乐观并发兜底 + 后台线程调度**」共同保证。四层从最内层页到最外层全局：

### 7.1 锁层次

```text
┌─ L4 全局/元数据层 ─────────────────────────────────────┐
│  BPM::latch_（缓冲池全局，串行化单次帧访问）            │
│  LockManager::meta_mutex_（跨分片元数据：等待图/归属）  │
└──────────────────────────┬─────────────────────────────┘
┌─ L3 分片锁层 ──────────────────────────────────────────┐
│  LockManager shard mutex ×16（锁表/谓词表按表哈希分片） │
│  表锁 / 行锁 / 谓词锁（多粒度 S/X，HierarchyConflicts）│
└──────────────────────────┬─────────────────────────────┘
┌─ L2 页级层 ────────────────────────────────────────────┐
│  Page 读写闩（shared_mutex，RAII PageReadGuard/        │
│  PageWriteGuard）——数据读写、B+Tree 结构访问           │
│  TableHeap per-table write_mutex_（写序列串行化）       │
└──────────────────────────┬─────────────────────────────┘
┌─ L1 磁盘/日志层 ───────────────────────────────────────┐
│  DiskManager::db_io_latch_ · LogManager::mutex_        │
└─────────────────────────────────────────────────────────┘
```

### 7.2 锁序不变量（死锁防护的契约）

任何线程持锁顺序必须满足以下偏序，反向即死锁风险：

1. **L2 页闩 → 不请求 L4**：持页闩期间绝不调用 `GetPage/NewPage/UnpinPage` 等 BPM 接口（分裂等需持多把写闩的场景用「先 pin 后加闩」绕过，即 pin 不是锁）；
2. **L4 内偏序**：`BPM::latch_ → LogManager::mutex_`、`BPM::latch_ → DiskManager::db_io_latch_`；
3. **L3 内偏序**：`shard mutex → meta_mutex_`（分片锁优先于全局元数据锁）；行锁与所属表锁**必须落在同一分片**（行资源按 `table_hint` 路由），保证层级冲突判定不跨分片持锁；
4. **等待不持锁**：行锁等待只在分片条件变量上等待（等待期间释放分片锁）；组提交领导者在时间窗内 `wait_for` 释放 `gc_mutex_` 允许跟随者登记。

### 7.3 并发策略分档

| 场景 | 策略 | 依据 |
|---|---|---|
| 页内容读写 | 页级读写闩（读者-写者） | 读写不互斥，写写互斥 |
| B+Tree 读路径 | **乐观重启**：共享闩快照 (pid, version)，校验失败整体重启，无锁等待 | 读不阻塞写、无等待环 |
| B+Tree 写路径 | 快路径只锁目标叶；慢路径带写闩下降 + 预分裂 | 写写串行、无级联分裂 |
| 同表并发写 | per-table `write_mutex_` 串行化「找页→判满→新建→链接→插入」整段序列 | 防链表分叉丢行（check-then-act） |
| 行/表锁 | 分片 S/X 锁 + 等待图 DFS 死锁检测 + 超时 | 多粒度收敛、O(1) 授予 |
| 谓词锁 | 居中区间树（每分片内），写前按 `(表, 列)` 精确匹配 | O(log P + K) 冲突查询 |
| 快照读 | 免读锁，版本链可见性过滤 + 低水位 O(1) | 读者永不阻塞 |

### 7.4 后台线程与调度（对照「进程调度」）

| 线程 | 调度方式 | 同步原语 |
|---|---|---|
| 后台刷脏 | `SQLCOMPILER_BG_FLUSH_MS` 周期唤醒；刷盘期间释放 `bg_mutex_` 让 stop 可置位 | `bg_mutex_` + `bg_cv_`（wait_for）+ `bg_stop_` 标志 |
| 后台真空 | 同刷脏模式（`bg_vacuum_ms`，默认关闭） | 独立 `bg_mutex_`/`bg_cv_` |
| 组提交 leader | 并发提交队列首个事务成为 leader，窗口内 `wait_for` 收集跟随者，统一快照 + 单次 `SyncOs` | `gc_mutex_` + `gc_cv_` |
| 回环网络块设备服务端 | 独立 `std::thread`，`select` 100ms 超时轮询 accept/请求 | `stop_` 原子标志 + 每请求加锁 |

要点：所有后台线程都遵循「周期唤醒 → 快照工作 → 记账 → 回睡」模型，失败不退出（刷盘/真空异常被捕获吞掉），退出时经 `Shutdown` 幂等收尾，避免悬挂线程与资源泄漏。

### 7.5 与课程概念的对应

- **互斥/信号量**：`std::mutex`/`shared_mutex`/条件变量；
- **读者-写者问题**：页级读写闩 + B+Tree 乐观读；
- **死锁四条件与处理**：锁序不变量消除循环等待；等待图 DFS 检测 + victim 中止 + 超时兜底；
- **进程调度**：后台线程周期调度（§7.4）、组提交领导/跟随者；
- **内存回收**：低水位判定 + 内联/后台真空；
- **置换**：LRU/FIFO/CLOCK/LRU-K + 温度感知（热页留池）。
