# 操作系统页面管理模块 — 设计技术文档

> 定位：本文系统阐述页面管理模块（页式存储 + 缓冲池 + 替换策略 + 持久化 + 并发）的独特设计思路、实现方案，并就「为何选择当前方案而非备选」给出性能、资源占用、兼容性、扩展性的对比分析。配套代码：`src/storage/*`、`include/index/PageGuard.h`、`tests/storage/storage_ut.cpp`。
>
> 说明（诚实的范围界定）：本模块是**数据库的缓冲层**，不含传统操作系统意义上的「进程调度器」。用户所关心的「页面置换 / 进程调度等核心机制」，在本模块中的对应物是三层调度——① 帧页面对缓存槽的**替换调度**；② 脏页写回的**后台 I/O 线程调度**；③ 多线程访问同一帧的**页级读写互斥调度**。本文第 4 节按此映射展开，并明示与真正进程调度的差异。

---

## 1. 模块定位

```
上层（存储引擎/目录/索引）-- PageGuard(RAII) --> BufferPoolManager -- BlockDevice --> 介质
```
- **页（Frame/Page）**：4 KB 定长、页号唯一；
- **缓冲池**：固定帧数组，负责「把热页留在内存、把脏页按时写回」；
- **DiskManager**：页分配/回收、页 CRC 校验、跨重启空闲页持久化、介质抽象；
- 贯穿三不变量：**WAL-before-data**、**恒定锁序 `latch_→{Log, Disk}`**、**旁路兼容（不改既有文件格式）**。

全部指标由单元测试锁定（`storage_ut`）；详见 §验证链路与《存储子系统最终验收报告》。

## 2. 内存管理策略

### 2.1 固定帧池 + 页表 + 空闲帧优先复用

- 构造时一次性 `std::vector<Page>` 预分配 `pool_size_` 帧，**内存上限 = 帧数 × 页大小**，可经 `FramesForBytes` 将字节上限换算为帧数（E6）。固定池避免频繁 malloc，换取稳定延迟。
- `page_table_: map<page_id,frame_id>` 维护逻辑页→物理帧映射；`free_list_` 存放当前空闲帧。
- 分配顺序：**优先复用空闲帧**（零拷贝、无 I/O）→ 惰性淘汰替换器中的帧；写回旧帧再复用。

### 2.2 为什么不选「按需动态扩容」？
| 维度 | 固定池（选用） | 动态扩容（备选） |
|---|---|---|
| 延迟 | 恒定，可预测 | 扩容触发 malloc/换页抖动 |
| 资源占用 | 上限可配置、可观测 | 峰值难控 |
| 实现复杂度 | 低，无重哈希/重排 | 需动态重分配 + 指针失效处理 |
| 取舍 | 命中 WAL/LRU 语义更直白 | 工程收益不成比例 |

## 3. 页面置换算法

所有替换器实现统一 `Replacer` 接口：`Pin (占用)、Unpin (允许淘汰)、Victim (选帧)、Size`。替换器不碰缓冲池内部，策略可插拔（构造入参 `ReplacementPolicy`），默认 **LRU**，扩展 **FIFO / CLOCK / LRU-K**。

### 3.1 各算法原理与复杂度
| 算法 | 原理 | 「被选中淘汰」成本 | 命中率 | 实现 |
|---|---|---|---|---|
| **LRU** | 淘汰最近最久未用 | O(1)，map 记录 | 好 | 优先队列/链 |
| **FIFO** | 淘汰最先进入 | O(1) | 差（无访问性） | 普通队列 |
| **CLOCK** | 二次机会，参考位 | O(n≤frames) | ≈LRU 且不重排序 | 环形指针 |
| **LRU-K** | 参考最近 K 次，保护热点页 | O(log n) | 对顺序扫描最优 | 双集合(R-B tree/set) |

### 3.2 LRU-K 双集合设计（E8 亮点）
`recent_store_`（访问次数 < K）与 `historic_store_`（访问次数 ≥ K）两个有序集合：
- **非相关页**（引用次数不足 K，多为一次性/顺序扫描页）先被淘汰——这是 LRU-K 抗扫描的核心；
- **相关页**（访问 ≥K 的热点）按「第 K 次访问时间」排序，避免被顺序流挤出；
- K=1 退化为普通 LRU，接口向下兼容。

### 3.3 为何默认 LRU，而非一开始就上 LRU-K/CLOCK？
| 考量 | 结论 |
|---|---|
| 性能 | 本模块单连接、访问局部性明确，LRU 命中率已足够；LRU-K 相对优势要在含顺序扫描的负载下才拉开 |
| 资源占用 | LRU 恒定 O(pool)，无堆栈开销；LRU-K 需额外访问历史，增内存与 log 排序成本 |
| 兼容性 | 默认 LRU 与历史 Phase A/B 行为逐字节一致，零迁移 |
| 扩展性 | 走 `Replacer` 抽象，LRU-K/CLOCK 均已接入并单测，切策略不改业务代码 |
> 结论：**把可插拔作为架构，把简单可靠作为默认** —— 用接口红利留足扩展，用保守默认守住兼容。

### 3.4 与「进程调度」的映射
替换器即**帧的 CPU 调度器**：谁享有缓冲资源（被 Pin）、谁让出（被淘汰）。CLOCK 用「参考位」类似时间片轮转的二次机会；LRU-K 类似「最短下次使用」对热点任务的优待。但这不是进程调度——开销、抢占、优先级反转等问题不在本层语义内。

## 4. 调度相关机制（后台 I/O 线程 + 页级并发）

### 4.1 后台异步刷脏线程（E5）
- 独立线程周期性 `wait_for(interval)` → 复用免锁 `FlushAllDirtyUnlocked` 把脏页写回 **OS 缓存**。
- **关键不变量**：只写缓存、**不调 `Sync()`** —— 真正落盘仍由 Commit 路径的组提交 fsync 负责，因此 **group-commit 的 fsync 次数不变**；同时天然遵守 WAL-before-data（先 log Flush 再写页）。
- 为何不改为后台直接 fsync 落盘？→ 那会把 fsync 次数从「每 Commit 一次」升级为「后台高频」，放大组提交损失；且破坏崩溃点在 Commit 边界的可复现性。

### 4.2 页级读写锁（E4）
- 每帧一个 `std::shared_mutex`，`PageReadGuard`（共享读）/`PageWriteGuard`（独占写）RAII 持锁。
- **锁序**：全局 `latch_` → 页锁；持页锁期间禁止调用 BPM 方法。
- 四条写回路径落盘前取该帧**读锁**，防止并发写者撕裂正落盘的数据。
- 为何用 `shared_mutex` 而非大锁→让多线程对相同热页并发读、串行写，`\stats` 单测证明读写互斥撕裂为 0、共享并发峰值 ≥2。

## 5. 持久化与崩溃一致性（D5 + 空闲页）

- **WAL-before-data**：写盘前保证 `page_lsn ≤ durable_lsn`；Commit 时组提交先 fsync WAL 再 `Sync()` 数据+校验。
- **页 CRC（`.crc` 旁路）**：每页 4 字节 CRC，惰性创建、默认加载旧库为空则跳过校验（后端兼容）；写回只 flush 到 OS 缓存，与组提交同批落盘，fsync 次数不变。
- **空闲页位图（`.fpl` 旁路）**：`pages`、magic、version 三校验；位 i=1 表示空闲，**复用前先置 0 并持久化**，杜绝崩溃后双重分配。
- **fsync 顺序（本次修复 #2）**：`.crc` **先于**数据页 fsync。若颠倒，断点在两次 fsync 之间会产生「数据新、校验旧」且无法被 redo 自愈的假损坏；校验先行则数据落后可被 redo 重写并连带刷新 CRC，两态自洽。

### 5.1 为何用「旁路文件」而非「改主格式」？
| 维度 | 旁路 `.crc/.fpl`（选用） | 内嵌主文件（备选） |
|---|---|---|
| 兼容性 | 旧库直接打开，零迁移 | 需迁移工具，破坏既有库 |
| 扩展性 | 相互独立、可单独演进 | 耦合紧 |
| 代价 | 多两个文件句柄 | — |

## 6. 方案取舍小结（对照用户关注四维）

| 需求点 | 当前选择 | 理由（一次概括） |
|---|---|---|
| 内存管理 | 固定帧池 + 字节上限换算 | 延迟稳定、上限可配、简单 |
| 页面置换 | LRU 默认 + Replacer 可插拔（FIFO/CLOCK/LRU-K） | 简单可靠默认，接口红利留扩展 |
| 替换/IO 调度 | 替换调度 + 后台线程(不 Sync) + 页级读写锁 | fsync 次数不变、多读单写、锁序防环 |
| 持久化 | WAL-before-data + 旁路 CRC/空闲位图 + 校验先落盘 | 崩溃自洽、旧库兼容、无迁移 |
| 介质 | BlockDevice 抽象（File + FaultInjecting 装饰器） | 可测、可注入故障、透明替换 |
