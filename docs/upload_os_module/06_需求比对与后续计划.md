## 4. 后续开发计划

> 以相对周期（W = 周）排布，可依团队节奏平移。每周期含任务分解、验收口径与预期成果。

### 周期 1（W1–W2）：谓词锁扩展至任意列 + 复合索引区间推导 —— 消灭理论幻读窗口 ✅ 已完成

- **任务分解**
  1. `LockManager` 谓词注册由「主键区间」泛化为「(表, 列, 区间)」，冲突判定改为按列匹配；
  2. 执行器扫描路径收集**任意等值/范围列谓词**（不只主键）注册读谓词；
  3. 写算子按受影响列做 `CheckWritePredicate` 冲突检查；
  4. `BPlusTree` 多列键区间推导：从最左列推进到**多列前缀区间**（lo/hi 多列复合下界）；
  5. 新增测试：非主键范围幻读复现用例 + 复合索引区间收敛断言。
- **预期成果**：SERIALIZABLE 幻读窗口关闭；`TestSerializablePredicatePhantom` 扩展至非主键列；
  复合索引扫描页数下降可量化。
- **验收**：新增 UT 断言 ≥ 8 组全绿；SQL 回归 55 条不回退。

#### 周期 1 完成记录（实现要点）

1. **谓词锁泛化至任意列**（`include/storage/LockManager.h` + `src/storage/LockManager.cpp`）
   - 谓词注册由「主键区间」泛化为 `(表, 列, 区间)`：`AcquireReadPredicate` 新增
     `column` 参数（`-1` = 全表/表级谓词），按表组织 `PredicateTableGroup`，
     列级谓词用**居中区间树**管理（开边界：lo 空 = -inf、hi 空 = +inf），
     O(log P + K) 冲突查询；`CheckWritePredicate` 按 `(表, 列)` 精确匹配，
     全表谓词与列谓词按区间相交判定，互不误伤。
2. **执行器任意列谓词收集**（`src/execution/ExecutionEngine.cpp`）
   - `CollectScanPredicates` 重构：从索引边界 + `Filter` 谓词中**同时**提取
     等值/范围列约束，解析列下标与运行时类型（`BuildIndexKeyTypes` +
     `LiteralToValue`），生成 `(表, 列, 区间)` 读谓词并注册；支持单列谓词与
     表级全表谓词两条路径。
3. **写算子按列冲突检查**（`src/execution/Executor.cpp`）
   - `CheckSerializablePredicate` → `CheckWritePredicateRow`：对 INSERT/UPDATE
     写入行的**每一受影响列**逐个检查列级谓词（按表 + 列名查列下标），
     SERIALIZABLE 下命中即阻塞/终止，闭合非主键列幻读窗口。
4. **复合索引多列前缀区间推导**（`include/plan/Plan.h` + `src/optimizer/IndexAccessPath.cpp`
   + `src/plan/Plan.cpp` + `src/execution/IndexScanExecutor.cpp`）
   - `IndexScanNode` 新增 `low_bound_cols` / `high_bound_cols`（前缀边界列数）；
   - 优化器按**最左前缀原则**逐列推进：等值列 push 进 lo/hi 并累计前缀数，
     首个范围列只推边界并**停止推进**，无约束列即停；首列范围退化为单列边界；
   - 执行器 `CompareKeyPrefix` 按前缀列数比较复合键，`BeyondUpperBound` /
     `InScanBounds` / `Next` 全部改用前缀比较，避免引入冗余哨兵值、不丢行不超界；
   - `EXPLAIN` 输出 `low=/high=` 前缀端点（`Plan.cpp`），便于测试断言收敛。
5. **新增 UT**（`tests/storage/storage_ut.cpp`，共 20+ 组新断言）
   - `TestSerializablePredicateNonPkPhantom`：二级索引非主键列 `g>=50` 范围谓词
     注册后，他事务插入 `g=60` 被阻塞（幻读窗口闭合）；插入 `g=10`（区间外）不被阻塞
     —— 并发性保持（≥9 组断言）；
   - `TestCompositeIndexRangeConvergence`：复合主键 `(a,b)` 上 `a=1 AND b>5` 收敛为
     `low=[1,5]`（2 列）`high=[1]`（1 列）、`a=1 AND b=2` 收敛为两列点区间、
     `a>5` 退化为单列下界；并对收敛后扫描做**不丢行/不超界**正确性校验（≥12 组断言）；
   - 既有谓词测试适配 `(表, 列, 区间)` 新签名。
- **测试证据**：`storage_ut` 58364 checks / 0 fails（PASS）；SQL 回归 55/55 通过
  （含 49/50 崩溃注入两阶段）；日志见 `docs/test_evidence/sql_regression_run.log`。

### 周期 2（W3–W4）：谓词区间树增量插入 + 组提交时间窗聚合

- **任务分解**
  1. 区间树改为**增删点更新**（插入/删除按区间端点二分定位），避免整树重建；
  2. `LogManager` 组提交引入**时间窗聚合**（`SQLCOMPILER_GROUPCOMMIT_WINDOW_MS` 可配），
     窗口内提交合并为一批 fsync；
  3. 基准对比：时间窗 vs 纯跟随者聚合的 fsync 次数与延迟曲线。
- **预期成果**：单语句大量区间注册开销 O(P log P)→O(log P)；高频小事务 fsync 次数进一步下降（在 9.8× 基础上再压缩）。
- **验收**：UT 覆盖增量插入正确性；组提交基准输出 fsync 数下降百分比；回归全绿。

### 周期 3（W5–W6）：温度阈值自适应 + LockManager 热点消除

- **任务分解**
  1. 温度阈值按**访问分布动态估计**（结合 LRU-K 频率信号），热页判定与淘汰策略联动；
  2. `LockManager` 按表/命名空间**分片锁**（shard）替代全局互斥，热点路径细粒度化；
  3. 压力测试：多线程同表/异表 DML 下锁管理器吞吐对比。
- **预期成果**：温度感知刷盘命中率提升可观测；锁管理并发吞吐提升有实测数据。
- **验收**：UT 新增断言；压力基准输出吞吐对比；回归全绿。

### 周期 4（W7–W8）：调参实验与交付固化

- **任务分解**
  1. 缓冲池帧数 / 后台刷脏 / 后台真空 / 组提交窗口**参数扫描实验**，固化「推荐配置」与基准曲线；
  2. 交付文档补充：环境变量矩阵、运行截图、性能曲线图；
  3. 将 storage_ut + SQL 回归固化为**一键复现脚本**（含崩溃注入），输出统一证据包。
