# 隔离级别：全面行级并发 + SERIALIZABLE 谓词锁

## 一、目标与背景

现状 [ExecutionEngine.cpp](file:///c:/Users/Lenovo/Desktop/SQL-Compiler/src/execution/ExecutionEngine.cpp#L387-L457) 在语句边界对整表取 S/X 锁（`ExecuteSubplan`），导致同一张表上的两个事务被表锁串行化，行级 S/X 锁形同虚设。

本阶段目标（用户已确认）：
1. **全面行级并发**：READ COMMITTED / READ UNCOMMITTED / SERIALIZABLE 的 DML（INSERT/UPSERT/UPDATE/DELETE）与只读语句**都不再取表锁**，改由算子内部逐行取 S/X 锁支撑细粒度并发。
2. **SERIALIZABLE 也转行级**：通过**谓词锁**（predicate lock）防幻读，不依赖整表锁。
3. 为 B+Tree 补**树级读写锁**，取消表锁后索引并发读写才安全。

探查结论（前序已完成）：
- TableHeap 写路径已用【每表 `write_mutex_`】([TableHeap.h](file:///c:/Users/Lenovo/Desktop/SQL-Compiler/include/storage_engine/TableHeap.h#L101)) 串行化堆尾页扩展，堆层安全。
- B+Tree（[BPlusTree.cpp](file:///c:/Users/Lenovo/Desktop/SQL-Compiler/src/index/BPlusTree.cpp)）**无任何内部锁**：`Insert/Delete/SplitRoot/SplitChild` 是跨页 read-modify-write，`PageGuard` 只 pin 不持锁。取消表 X 锁后必发生数据竞争/页损坏。→ **必须先加树锁**。

## 三、拟改动方案

### Part 1：B+Tree 树级读写锁（前置，必须最先做）

给 `BPlusTree` 加 `mutable std::shared_mutex rw_lock_;`（需要 `#include <shared_mutex>`）。嵌套类 `Cursor` 可访问私有成员。

- **修改操作** `Insert` / `Delete`：方法体首行 `std::unique_lock<std::shared_mutex> u(rw_lock_);`（内部私有 `SplitChild/SplitRoot/FindLeafPage` 不重复加锁）。
- **只读点查** `FindFirst`：`std::shared_lock<std::shared_mutex> s(rw_lock_);`。
- **范围扫描** `LowerBound` / `Begin`：创建 `Cursor` 后对其成员 `scan_lock_` 赋值 `std::shared_lock<std::shared_mutex>(rw_lock_)`，使共享锁跨整个扫描生命周期保持。
  - `Cursor` 增加成员 `std::shared_lock<std::shared_mutex> scan_lock_;`（默认空锁，MoveAssignable）。
- **不触碰** `SetActiveTransaction/SetLogManager/Destroy`（`Destroy` 在表删除的 DDL 路径，仍由 DDL 表锁保护）。

权衡（写入注释）：树锁是粗粒度，同一表的写操作彼此串行、长扫描会阻塞该树写入。正确性优先，锁耦合（latch crabbing）列为后续可选项，本阶段不做。

### Part 2：放宽语句边界表锁（ExecutionEngine）

重写 [ExecutionEngine.cpp](file:///c:/Users/Lenovo/Desktop/SQL-Compiler/src/execution/ExecutionEngine.cpp#L414-L457) 的锁获取段：

- **新增判定** `bool IsDdlStmt(plan)`：根节点为 `TRUNCATE_TABLE / ALTER_TABLE / DROP_TABLE / CREATE_INDEX / DROP_INDEX / CREATE_TABLE` 时视为 DDL。
- **DDL**：保留现有表级 X 锁（目标表），持有到提交 — 结构性变更仍需表级互斥。
- **DML/只读**：**不再取任何表锁**。仅依赖：
  - 行级 S/X 锁（逻辑并发隔离）；
  - B+Tree 树锁 + TableHeap `write_mutex_` + BufferPool 页锁（物理安全）；
  - SERIALIZABLE 的谓词锁（防幻读，见 Part 3）。
- 删除不再需要的 `CollectScanTableNames` 表锁循环、`rc_read_res` 表读锁登记（行级 RC 读锁释放仍由既有 `ReleaseRowReadLocks` / `Executor.h` 的 `statement_row_read_locks_` 承担，逻辑不变）。
- 异常路径的锁回收逻辑收敛为：DDL 表锁 + 既有 `release_rc_read_locks`/`ReleaseRowReadLocks`。

### Part 3：SERIALIZABLE 谓词锁（LockManager + 算子接入）

在 `LockManager` 增加**谓词锁**设施，防幻读（目标/范围/全扫描的行集在提交前不被他事务写入覆盖）。

数据结构（`LockManager` 私有）：
```
struct PredicateLock {
    int64_t txn_id;
    int64_t table_rid;      // 表堆首页页号，与表锁/行锁同命名空间
    bool is_full;           // 全表谓词（seq scan / 无键范围）
    IndexKey lo, hi;        // is_full=false 时的 [lo, hi]（主键区间）
};
std::vector<PredicateLock> pred_locks_;
```
谓词作用在**主键键空间**。`IndexKey` 比较复用 `CompareKeyOnly`。

新增公开 API：
- `LockResult AcquireReadPredicate(int64_t txn_id, int64_t table_rid, bool is_full, const IndexKey& lo, const IndexKey& hi)`：SERIALIZABLE 范围/全扫描注册读谓词。多个读谓词共享共存；不立即判断冲突，也发给已持谓词/持行锁本事务去重。持有到提交，由 `UnlockAll` 一并释放。
- `LockResult CheckWritePredicate(int64_t txn_id, int64_t table_rid, const IndexKey& key)`：**写前调用**。遍历 `pred_locks_` 中**其他活动事务**同表谓词；若某谓词 `is_full` 或谓词区间覆盖 `key`，则：
  1. 在 `waits_on_[txn]` 加入指向谓词持有者 txn 的等待边；
  2. 对新边跑既有 `DeadlockCycle` → 成环返回 `kDeadlock`（调用方中止本语句），否则**阻塞等待**该谓词持有者提交（复用 `cv_`）；
  3. 谓词持有者提交（`UnlockAll`）时清理其谓词 → 唤醒阻塞写者重试。

写算子接入：`InsertExecutor / DeleteExecutor / UpdateExecutor / UpsertExecutor` 在**以主键写某行之前**，若当前事务 `IsolationLevel == kSerializable` 且行有主键，调用 `CheckWritePredicate`。

读谓词注册：在 `ExecutionEngine::ExecuteSubplan` 语句前置阶段，对 SERIALIZABLE 且含扫描的计划注册读谓词——
- 计划仅含 `SEQ_SCAN`（无 key）→ `is_full=true`；
- 计划含 `INDEX_SCAN` 且有 `low_key/high_key` → `is_full=false`，取对应区间（`SEQ_SCAN` 的 key 为上界/下界）；`is_full` 优先合并。

**限制（写入文档）**：谓词只覆盖主键键空间；非主键索引透明，靠行锁+树锁保证物理与已存在行的一致，幻读保护仅覆盖主键区间——作为本阶段可交付的正确性边界，避免过度设计。

## 四、假设与决策

1. **B+Tree 用树级 `std::shared_mutex`**，不做页级锁耦合（工作量/风险权衡，读者自行扫描一致性；扫描期间该树写被阻塞）。
2. **DDL 保留表 X 锁**，不划入行级。
3. **谓词锁在冲突时阻塞而非任意中止**，保持串行化语义；死锁时按既有判定中止 victim。
4. 谓词锁基于主键键空间；非主键索引的幻读保护不在本阶段范围。
5. 既有的 `TestIsolationLevels` 依赖表锁阻塞并发写，需按新语义改写（改为用行锁/谓词验证）。
