## 1. 页式存储与持久化

### 1.1 空闲页跨重启持久化

| 方案 | 说明 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 旁路 `.fpl` 位图文件 | 24B 头 + 位图（位 i=1 ⇒ 页空闲），惰性创建 | 零数据文件布局变更、旧库逐字节兼容；位图 O(1) 判空 | 双文件需保持一致性 | **采纳**：跨重启可复用空闲页，且不冒迁移风险 |
| B. 页头空闲标志 | 页内预留位标记空闲 | 单文件 | 改数据文件布局；崩溃时标志与内容可能不一致 | 不采纳 |
| C. 独立 meta 页/表 | 文件内固定 meta 页存空闲列表 | 单文件 | 缩文件/扩文件时 meta 偏移复杂；崩溃一致窗口更大 | 不采纳 |
| D. 启动扫描全文件 | 重建空闲集 | 无附加文件 | O(文件大小) 启动开销；无法区分「从未分配」与「已释放」 | 不采纳 |

**当前设计独特性**：`.fpl` 装载时校验「位图页数 == 由数据文件大小推导的 next_page_id_」，不符即安全丢弃（**数据安全优先于空间复用**）；复用前先清位并持久化（**杜绝崩溃后双重分配**）；幂等 Deallocate。

### 1.2 页损坏检测

| 方案 | 说明 | 结论 |
|---|---|---|
| A. 旁路 `.crc` 文件（每页 4B CRC32） | 写路径记录、读路径核对、回收清除；0=无记录兼容旧库 | **采纳**：与 `.fpl` 同思路，零布局变更 |
| B. 页头内嵌 CRC 字段 | 单文件 | 改数据页布局（页大小固定 4KB 时挤占内容区）→ 不采纳 |
| C. 文件级整体校验 | 启动时全文件算一遍 | 无法定位页级坏块、无法运行时拦截 → 不采纳 |

### 1.3 真持久 fsync

| 方案 | 结论 |
|---|---|
| A. Windows `_commit(_fileno(FILE*))` / POSIX `fsync`（平台分支） | **采纳**：真正刷到持久介质 |
| B. `fstream::sync`（MSVC） | 仅刷到 OS 缓冲，掉电丢失 → 不采纳 |
| C. `FlushFileBuffers`/`fsync` 混用 | 平台内聚差 → 不采纳 |

## 2. 缓存管理

### 2.1 替换策略族（策略模式，可插拔）

| 方案 | 原理 | 复杂度 | 命中率 | 结论 |
|---|---|---|---|---|
| A. LRU | 双链表 + 哈希定位器，O(1) 访问/淘汰 | O(1) | 基准 | 内置（指导书必修） |
| B. FIFO | 队列 + 集合延迟删除 | O(1) | 低于 LRU | 内置（指导书必修） |
| C. CLOCK | 环形指针 + 参考位二次机会 | O(1) | ≈ LRU | 内置（折中） |
| D. LRU-K | 双集合：recent(<K 访问) + historic(≥K)；K=1 退化为 LRU | O(1) 均摊 | **≥ LRU**（抗顺序扫描污染） | **默认**（`SQLCOMPILER_REPLACER` 可切） |

**优越性**：策略模式接口隔离算法与缓冲池本体，新增算法零侵入；LRU-K 兼顾扫描抗污染与 O(1) 开销，实测命中率 ≥ LRU。

### 2.2 缓冲池并发

| 方案 | 结论 |
|---|---|
| A. 全局互斥锁 | 串行化所有帧访问 → 不采纳（吞吐瓶颈） |
| B. 帧分桶锁 + 全局闩分层 | 单次帧访问由全局闩串行化，跨次访问用 per-table 写互斥锁串行化整段写序列 | **采纳**：锁序 `latch_ → LogManager::mutex_`、`latch_ → DiskManager::db_io_latch_` 无环；页级读写闩防写盘撕裂 |
| C. 无锁哈希表 | 实现复杂、调试困难 → 不采纳 |

## 3. 索引并发（B+Tree）

| 方案 | 说明 | 结论 |
|---|---|---|
| A. 树级粗粒度锁 | 读写互斥、无并发 | 基线（被超越） |
| B. 页级闩 + 乐观重启 | 读路径共享闩快照 (pid,version) 校验，失败整体重启（上限兜底）；写路径快/慢分档，慢路径带写闩下降 + 预分裂；「先 pin 后加闩」持多把写闩不违锁序 | **采纳**：读不阻塞写、无锁等待、无等待环；实测 16 线程 **3.18×** |
| C. B-link 兄弟指针 | 无需重启但格式改动大、实现复杂 | 不采纳 |
| D. 手风琴/足迹协议 | 结构性高开销 | 不采纳 |

**独特性**：版本号复用页头 offset-12 保留字段（**零页格式变更**）；游标「物化快照 + 版本校验 + 重定位」保证并发扫描不跳不重；U1 系列再平衡（删后 <40% 合并、根收缩）+ TryFreePage 物理删页可靠回收。

## 4. 事务、锁与隔离

### 4.1 锁管理结构

| 方案 | 结论 |
|---|---|
| A. 单全局锁表 + 全局互斥 | 热路径串行 → 不采纳 |
| B. **16 分片 + splitmix64 哈希**：表锁/行锁/谓词锁按表哈希分片；行锁经 table_hint 与所属表锁同片；跨片元数据（等待图/归属）持 meta_mutex_ | **采纳**：行锁热路径带 table_hint 跳全局互斥，层级冲突判定不跨片持锁；锁序 `shard → meta_mutex_` |
| C. 无锁等待图 | 复杂度高 → 不采纳 |

### 4.2 死锁处理

| 方案 | 结论 |
|---|---|
| A. 超时放弃 | 简单但误杀长事务 → 兜底（5000ms 表锁超时） |
| B. **等待图 DFS 检测 + victim 中止** | **采纳**：精确成环检测；victim 返回 kDeadlock 前撤销自身等待边防残留；TryLock 探针保留等待登记边使后续成环可被检出 |
| C. 锁序静态预防 | 与行锁动态获取冲突 → 仅作约束（锁序不变量） |

### 4.3 隔离级别（RC/RR/SERIALIZABLE/SNAPSHOT）

| 方案 | 结论 |
|---|---|
| A. 全部用 S/X 锁（SERIALIZABLE 风格） | 读者阻塞写者 → 不采纳 |
| B. RC 语句末释放读锁 + RR 提交释放 + SERIALIZABLE 谓词锁防幻读 + **SNAPSHOT 免读锁 + FCW** | **采纳**：读多写少场景读者永不阻塞；FCW 提交期比对快照读基拦截丢失更新 |
| C. 全部 MVCC（无锁） | 写写冲突检测成本高 → 不采纳 |

### 4.4 谓词锁区间树

| 方案 | 结论 |
|---|---|
| A. 谓词线性表扫描 | O(P) → 不采纳 |
| B. 排序列表 | O(P) 插入 → 不采纳 |
| C. **按表组织的居中区间树**（分裂点=lo 中位数；增量更新 O(D log P) 摊薄 + 脏标记惰性重建；全表谓词作全域哨兵） | **采纳**：O(log P + K) 冲突查询；写前按 (表,列) 精确匹配 + 区间相交判冲突 |

### 4.5 MVCC 优化族

| 机制 | 备选 | 结论 |
|---|---|---|
| 快照低水位 | 每次扫描活动快照 O(n) / **事件驱动缓存 + 惰性重算 O(1)** | 采纳后者：10k 读 157µs（≈465×） |
| 版本链查询 | 沿 prev 链线性扫 / **内存版本索引缓存（rid→按 begin_csn 排序数组，5 元组头槽校验）** | 采纳后者：纯内存、零磁盘格式变更 |
| 真空 | 全表周期扫 / **写路径内联回收（每语句预算）+ 后台低频兜底** | 采纳后者：滞后版本 91.7% ↓ |

## 5. 日志与恢复

### 5.1 WAL 提交同步

| 方案 | 结论 |
|---|---|
| A. 每事务独立 fsync | 吞吐受磁盘 IOPS 上限 → 基线 |
| B. **组提交（leader-follower + 可调窗口）** | **采纳**：统一快照 + 单次 SyncOs；128 并发提交 = 12~13 次 fsync（**9.8~10.7×**）；窗口参数扫描推荐 **10ms**（fsync -17%、膝点） |
| C. 关闭同步（牺牲持久性） | 不采纳 |

### 5.2 刷脏时机

| 方案 | 结论 |
|---|---|
| A. 淘汰时全部写回 | 每页一次 IO → 基线 |
| B. **温度感知刷盘**（access_count_ 热度 → 只写冷脏页、热页留池；NO-FORCE+WAL 兜底） | **采纳**：削减写 IO 且保留热页命中率；自适应阈值（P 百分位）+ 平坦分布守卫 + 边界分层守卫 |
| C. 后台线程全量刷 | 与 B 组合（`SQLCOMPILER_BG_FLUSH_MS`） |

## 6. 查询优化（Phase 6 U3，编译模块与 OS 模块的协同）

| 机制 | 备选方案 | 结论 |
|---|---|---|
| 子查询 | A 逐行重跑 / B 仅非相关物化 / C **安全形态改写 SEMI/ANTI JOIN + 非相关物化 + 递归 CTE 失效** | 采纳 C：EXISTS/IN/ANY 主体 N×M → 一次连接；NOT IN（NULL 语义）等疑点四道守底闸保持原路径零回归 |
| JOIN 顺序 | A 原序 / B **全 INNER 左深链按估计基数小表驱动重排（就近贪心）** | 采纳 B：OUTER/未限定列守底原序 |
| 聚合 | A 线性分组（AggregateExecutor）/ B **单表裸 COUNT/SUM 扫描层哈希预聚合（PreAggScan）** | 采纳 B：O(1) 均摊分组；AVG/DISTINCT/包装 守底零改写 |
| 物化缓存 | A 无缓存 / B **语句级缓存（键=subquery_plan 指针）+ 观测 sink** | 采纳 B：快照隔离下语句级即一致；未限定列保守不入缓存 |

## 7. 设计哲学总结

1. **零磁盘格式变更**：版本号、版本索引、统计全部进程内，`.fpl`/`.crc`/WAL/48B 版本头布局不变 → 向后兼容、低迁移风险；
2. **保守守底优先**：任何「可能等价但无法静态证明」的改写一律保持原行为（NOT IN、未限定列、OUTER JOIN、AVG 聚合）→ 零回归；
3. **可观测优先**：`\stats`/`\analyze`/`\bench` 全指标（命中构成、脏页年龄、锁等待分布、子查询缓存计数）→ 性能与正确性都可证据化；
4. **分层锁序契约**：四层锁层次 + 严格偏序 + 乐观并发兜底 + 后台线程调度 → 并发正确性可论证、可测试。
