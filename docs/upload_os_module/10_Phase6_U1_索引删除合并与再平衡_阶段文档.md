## 2. 本阶段实现的功能与技术细节

### 2.1 删除后下溢再平衡 `BPlusTree::RebalanceAfterDelete`

触发：`Delete` 与 `Vacuum` 移除条目后，目标叶 `LeafUnderfull`（占用字节 < 页面 `kUnderfullRatio=0.40`）时调用，
以刚删除的键为探针**带写闩下降**定位其直接父节点，随后对**同一父节点下的相邻兄弟对**做再分配。

核心步骤（`src/index/BPlusTree.cpp`）：

1. **带写闩下降定位父 / 兄弟**：从根沿 key 路由下降，在每个内节点持写闩读取孩子列表，直到命中 `curtgt` 的直接父 `parent_pid` 与该子树位置。带环路防御（`visited` 集合）。下降过程单步持闩、逐级释放，任一层面键已迁移找不到父则**保守放弃**（返回 0），绝不破坏结构。
2. **确认仍下溢**：取 `curtgt` 写闩前先读闩复核当前仍为叶且仍下溢（并发已回填则跳过）。
3. **读闩下复读父内容**，据 `curtgt` 相对位置确定左右兄弟 `left_pid` / `right_pid` 与父子分隔键下标。
4. **先 pin 再加闩**：对 `parent / left / right` 三页先 `PageGuard::Fetch`（仅 pin、无闩），再 `LatchPinned` 按 **父 → 左 → 右** 顺序取写闩（与分裂路径 `SplitChild` 的「先 pin 后加闩」一致，无循环等待）。
5. **闩下复核**：重读父内容，在「闩下」重新由左右孩子下标算出父子分隔键槽下标并校验相邻性（`rch == lch + 1`、`pents2[sep_idx].child == right_pid`），杜绝 step3→step4 之间父内容并发变化导致的越界。
6. **借入量计算**：以探针副本迭代，直到借入方不再是下溢叶、且借出方至少保留一条（保证右侧永不缺分隔键）。
7. **整批移动 + 整页重写 + 父分隔键更新**：从较满一侧借条目到欠满一侧；父子分隔键取右孩子新首条完整 `(key, rid)`。
8. **持久化**：被改动的三页均整页重写（内建版本号自增 + WAL before/after 镜像）；**脏标记设置在拥有 pin 的 `PageGuard` 上**（见 §4.2 修复）。

再平衡是**叶级局部修复**：父的孩子数不变（只改一个分隔键槽值），故**不向上级联**；内节点下溢合并与物理删页按计划在 U1b 交付（本阶段用「借 + 整页重写」规避被回收页被并发读回的窗口）。

### 2.2 可观测性

- `BPlusTree::GetHeight()`：沿最左路径读闩下降计数（单叶 = 1）。
- `BPlusTree::ComputeUtilization()`：遍历全部叶/内节点，统计 `min_ratio`（最小页利用率）、`avg_ratio`（平均）、`leaf_pages`、`internal_pages`。
- `SystemCatalog::CollectIndexStats()`：汇总全部索引树的树高与利用率。
- `\stats` 新增 **indexes** 段：每索引输出 `[name] height / avg / min / leaf / int`。

### 2.3 删除路径并发安全修正（回归）

对 `Delete` 的首叶（`step==0`）版本不匹配处理做了修正：原先 `continue` 落到 `step==1` 会**无版本复核地重读同一首叶**，
在并发分裂/再平衡把目标键迁移到相邻叶后，会在旧叶找不到键而静默漏删或错删。改为置 `restart` 标志 → 整体重启下降、
重新按 key 路由定位目标叶（沿用「首叶版本检查不足 → 需重路由」的历史结论）。

## 3. 与备选方案的对比（技术优越性 / 性能优势 / 适用场景）

| 备选方案 | 本方案 | 优劣势 |
|---|---|---|
| **B 树式就地借一条**，逐条移动并更新多个分隔键 | **整批移动 + 单分隔键更新**（右首条 `(key,rid)`） | 每次再平衡只写 3 页、只改 1 个父子槽，O(1) WAL/锁开销；无逐条跨叶的中间态一致性成本 |
| **立即物理合并删页**（两叶内容整体迁移并回收被弃页） | 本阶段只做**再分配**，不改叶链、不物理删页 | 原样迁移会引入「被回收页恰被乐观游标当作 next_leaf 读回 → 重复/漏发条目」的窗口；再分配只移动条目 + 所在叶整页重写，游标跨叶前进前校验版本即可感知并重定位，**无重复、无丢键**，且无需为新阶段实现 epoch 引用计数。物理合并/回收留给 U1b（具备安全 epoch 机制后交付） |
| **仅靠后台 Vacuum 收紧** | Delete 在线触发 + Vacuum 兜底 | 在线再分配让点查/范围查成本在**实时删除负载**下即被控制，不依赖低频真空的滞后性 |
| **全树重建 / 托管式空间整理** | 局部兄弟们 + 单分隔键更新 | 开销与受影响范围成正比（只触及下溢叶所在子树的相邻页），非全量扫描重建 |

性能优势：单趟最多写 3 页、O(log N) 定位 + 常数借入，符合「删除自愈尽量局部化」的目标；`\stats` 索引健康让平均/最小利用率可直接观测，无需外部剖析工具。

适用场景：**任意工作负载中"删除或覆盖更新占比高、且长期运行"**的表（业务归档、日志清理、MVCC 长历史回卷）。读多写少或只增无删的场景，额外开销仅在下溢叶出现时发生，非持续热路径。

# U1b 增补 — 内节点下溢合并 + 物理删页 + 根收缩（2026-09-14）

> 在 U1（叶级再分配）基础上补齐「删除自愈」的下半截：**内节点下溢合并、级联回收被弃叶页、根收缩收树高**。U1 阶段明确把物理合并/删页推迟到具备安全 epoch 后交付，U1b 即该交付。

## U1b-1 关闭的缺口

| 编号 | 缺口 | U1b 处理 |
|---|---|---|
| N1a | U1 只做叶级再分配，**不改叶链、不物理删页**；长期删除下内节点可能下溢、被并叶页永不回收 | `RebalanceAfterDelete` 扩展为**叶 + 内节点统一再平衡**：叶下溢超过借条边界 → **整页合并 + 物理回收被弃叶（BPM `DeletePage` → `.fpl` 空闲位图）** → 父孩子数 -1 → 级联内节点合并 → 根单子收缩 |
| N1b | 无根收缩，多轮大删后树高不降 | `CollapseRootIfNeeded`：根为单子内节点时**就地改写根为子树拷贝并回收原孩子页**（根页 id 恒定），树高 -1 |

## U1b-2 实现细节（`src/index/BPlusTree.cpp`）

1. **统一再平衡 `RebalanceAfterDelete`**：带写闩下降定位父节点后，对下溢节点 `curtgt` 与左右兄弟先尝试**再分配**（U1 路径，局部修复不返级联）；再分配仍无法满足下溢（借入方仍 <40%）时转**合并**：
   - 取父写闩 + 左/右兄弟写闩（`先 pin 后加闩`，**父 → 左 → 右** 锁序，与分裂一致）；
   - 闩下复核相邻性（`rch == lch + 1`）后，把右（或左）兄弟全部条目搬入合并目标叶、整页重写（内建版本自增 + WAL 镜像）；
   - 父节点删除该孩子指针（**整页重写父**，孩子数 -1）；被并叶调 `BPM::DeletePage` **物理回收**；
   - 返回 `1 + child 返回值`：**级联** —— 父孩子数骤降可能使父本身下溢，递归对父再平衡（合并可一路向上）。
2. **根收缩 `CollapseRootIfNeeded`**：合并后根可能只剩一个孩子（内节点）；将根就地改写为唯一孩子的完整内容拷贝（`BPM::GetPage` 读孩子 → `WriteInternal/Leaf` 整页覆写根[或反之]），随后 `DeletePage` 回收原孩子页，树高 -1。根页 id 恒定（沿用 `SplitRoot` 约定），**须在不持任何页闩时调用**（自身会调 BPM 删页）。
3. **游标（乐观扫描）物理删页安全恢复 `Cursor::RelocateRestart`**：扫描前进时 `next_leaf` 指向的叶子可能已被本次合并**物理回收**（乐观读回已弃页→重复/漏发）。游标物化当前叶后记录**最近发出条目**与**扫描锚点**（`anchor_begin_`/`anchor_key_`）；当前叶版本变化导致 `next_leaf` 失效、或下一叶无法装载时，调用 `RelocateRestart`：按最近发出条目的下一项（或锚点）**重新乐观下降定位目标叶**（`OptimisticFindLeafPage`/最左叶 + `ValidatePath`），在其上从首个严格大于"已发最后条目"（或 `>=` 锚点）的位置续扫——**不丢、不重、不越界**。

## U1b-3 与备选方案对比

| 备选方案 | 本方案 | 优劣势 |
|---|---|---|
| **合并 + 悲观 epoch 引用计数**保护被回收叶 | **乐观游标重下降恢复**（`RelocateRestart`） | 不引入全局 epoch/引用计数，物理删页立即生效，`.fpl` 立即可复用；游标只在版本不匹配时作一次 O(log N) 重定位，扫描连续命中时零额外开销 |
| **根延迟收缩**（保留空根待后续插入复用） | **就地改写根 + 立即回收孩子页** | 立即回收、树高实时反映实际；根页 id 不变，无根页重建的引用失配 |
| **仅内节点合并、叶页保留供复用池** | **叶页也物理回收进 `.fpl`** | `.fpl` 位图机制让空间可被 `AllocatePage` 复用（U1b 实测 free 0→300），长期空间占用收敛 |

# U1c 增补 — 物理删页可靠回收（挂起队列 + 安全点排空）（2026-09-14）

> U1b 的合并/根收缩对 `BPM::DeletePage` 采用 best-effort：被并发读者 pin 时让出，页面不回收 → 长期删除负载下**被并页空间泄漏**。U1c 用「挂起队列 + 安全点排空」把回收变为**可靠、最终一致**。

## U1c-1 关闭的缺口

| 编号 | 缺口 | U1c 处理 |
|---|---|---|
| N1c | U1b 回收被并页为 best-effort：`bpm_->DeletePage` 失败（页仍被读者 pin）时直接放弃，页号不回 `.fpl`，长期删除负载下孤儿页累积 | `TryFreePage`/`DrainPendingFrees`：失败页入**挂起队列**，后续写操作入口（不持页闩时）整体**重试排空**，保证被弃页最终回到 `.fpl` 并可供 `AllocatePage` 复用 |

## U1c-2 实现细节（`src/index/BPlusTree.cpp` / `include/index/BPlusTree.h`）

- `TryFreePage(pid)`：先尝试 `bpm_->DeletePage(pid)`；**失败（pin>0）则入队去重**。此刻页仍分配于 BPM、不会交给 `AllocatePage`，故延迟回收**绝不导致页号复用错乱**。
- `DrainPendingFrees()`：锁定交换出整队、清空去重集，逐个重试 `TryFreePage`；仍失败者回队。**须在不持任何页闩时调用**（`DeletePage` 内部取 BPM 全局锁）。
- 挂起容器：`std::mutex pending_free_mutex_` + `std::vector` + `std::unordered_set`（去重防止并发双推）。
- 排空点：`Insert` / `Delete` / `Vacuum` 入口（尚未下降、不持闩时）各调一次 `DrainPendingFrees()`。
- 替换 U1b 两处 best-effort 调用点为 `TryFreePage`（合并被并叶、根收缩原孩子页）。

## U1c-3 与备选方案对比

| 备选方案 | 本方案 | 优劣势 |
|---|---|---|
| **在合并现场自旋重试**直至 DeletePage 成功 | **去重挂起队列 + 写入口排空** | 不自旋阻塞（并发长读不留死角）；排空拆到后续写操作、无持闩调 BPM 风险；去重避免并发双释放 |
| **引入全局 epoch 引用计数**管理删页 | 无害延迟回收（页仍分配、绝不复用，待读者 Unpin 后回收） | 无需改动全局并发模型；只在有剩余写操作时回收——读多写少场景回收稍滞后（安全、不泄漏） |

## U1c-4 测试（`tests/storage/storage_ut.cpp`）

- 无泄漏不变量：`live = GetNumPages() - GetNumFreePages() == 叶+内节点页数`。若被并页泄漏，`live` 会大于树真实页数，此判据确定性失败。
- `TestBPlusTreeReliableReclaim`：52000 键（h3）删大区间 → 合并回收 → 临时 Insert+Delete 触发排空 → 断言 `live==leaf+internal`（实测 live=221, leaf=217, int=4）→ 三轮 churn 后 `live` 稳定不增（无卡死弃页）。
- `TestBPlusTreeReliableReclaimConcurrent`：扫描线程持续持/放叶页 pin 制造 `DeletePage` 失败，删除线程合并删页（大概率入队）→ 扫描停止后再写触发排空 → 断言 `live==leaf+internal`（并发下 0 泄漏）。

# U1d 增补 — 乐观重启路径校验短路（结构变更计数）（2026-09-14）

> 关闭 **N2**：乐观只读下降的路径校验原本逐页重取版本，成本随树高 O(h) 线性增长；数据规模扩大（树高 >4）后重启开销上升。U1d 引入**树级结构变更计数**，把「下降期间无任何结构改写」的常见路径校验降为 O(1)——只复核命中叶子的版本，不再重取每个祖先页。

## U1d-1 关闭的缺口

| 编号 | 缺口 | U1d 处理 |
|---|---|---|
| N2 | 乐观下降后 `ValidatePath` 逐页重取路径上每页版本（每页则一次读闩 + 一次版本比较），校验成本随树高 O(h) 线性增长；高并发冲突造成反复重启时，扫描/点查热点受树高放大 | 下降起点记录**结构计数快照**（`mod_at_descent`）；`ValidatePath` 先判「计数未变」→ 仅复核叶子版本（O(1)）；仅当有结构改写才回退全路径逐页复核（O(h)，仍保线性）。正确性由「结构改写必自增计数 ⇒ 计数未变 ⇒ 祖先链路未被改写」保证 |

## U1d-2 实现细节（`include/index/BPlusTree.h` / `src/index/BPlusTree.cpp`）

1. **结构变更计数**：`mutable std::atomic<uint32_t> structure_mod_`；`BumpStructureCounter()` 在所有**结构改写**处自增——`SplitChild`（分裂改父子结构）、`SplitRoot`（根分裂）、`RebalanceAfterDelete` 的**合并删孩子**、**再分配改分隔键**、**根收缩**（共 6 处；`InsertIntoLeaf`/`Delete` 等仅页内内容改写、不改结构，不计数）。
2. **下降快照 `DescPath`**：在原逐页 `entries`（页号 + 版本）基础上，记录 `mod_at_descent` 与命中叶子的 `leaf_pid()`/`leaf_version()`；`OptimisticFindLeafPage` / `OptimisticLeftmostLeafPage` 在下降开始时采样 `structure_mod_.load()`。
3. **短路校验 `ValidatePath`**：
   - `structure_mod_.load() == path.mod_at_descent`（下降期间无任何结构改写）→ 取叶子读闩，仅复核 `ReadVersion == leaf_version`；命中则 `++stat_fast_validate_`（O(1)）。
   - 否则回退全路径逐页复核（`++stat_full_validate_`）。
   - 任一复核失败 `++stat_restarts_` 返回 false，调用方整体重启下降（与原有乐观重启语义完全一致，**不吞错、不放宽容差**）。
4. **可观测性**：`GetOptimisticStats(fast, full, restarts, mod)` 暴露三条统计与当前计数，用于 UT 断言「纯读阶段全命中短路、无回退、无重启」。

## U1d-3 与备选方案对比

| 备选方案 | 本方案 | 优劣势 |
|---|---|---|
| **保留逐页全路径校验**（原实现） | **结构计数短路 O(1)** | 常见无并发改写的下降免去 h 次读闩/比较；结构改写仍走 O(h) 全路径，行为保守不后退 |
| **用全局 epoch + 引用计数判路径是否失效** | **单原子计数 + 叶子版本复核** | 无 epoch 管理、无需暴露阶段；结构改写才回退，读读并发零额外校验 |
| **在每页写时把路径所有祖先标记为无效** | 树级计数短路（聚合维度） | 省去每步传播与逐祖先判定；只用一次比较判定整个下降区间无结构改写 |

性能收益：单次读路径校验从 O(h) 读闩/比较降为 O(1)（1 次叶子读闩 + 1 次计数比较）；在高并发只读热点上也只读叶、不扰动内节点缓存行。
