# 操作系统页面管理模块 · 功能测试方案

- 项目：SQL-Compiler 小型数据库系统（编译原理 + 操作系统 + 数据库 三模块综合实训）
- 被测对象：**操作系统页面管理模块**（页式存储 / 缓冲池 / 替换策略 / 持久化 / 事务并发与崩溃恢复）
- 依据：《大型平台软件设计实习》指导书 三.2「操作系统页面管理」+ 本模块扩展开发（E1–E8 扩展、隔离级别、OS 优化 Phase 1–4）
- 编制日期：2026-09-13

---

## 1. 测试目标

1. 验证模块满足指导书全部必修要求：页式存储模型、缓存管理（LRU/FIFO）、命中统计与替换日志输出、统一存储访问接口、与执行计划对接、数据持久化、空闲页管理、错误处理。
2. 验证扩展开发成果的正确性：空闲页跨重启持久化（`.fpl`）、页 CRC 损坏检测（`.crc`）、真持久 fsync、组提交、页级读写锁、后台刷脏、内存上限配置、块设备故障注入、LRU-K/CLOCK 替换、页内分配器、事务隔离级别、MVCC 快照、谓词锁、WAL 崩溃恢复、B+Tree 乐观页级并发、快照水位 O(1)、内联真空、索引墓碑回收、谓词锁区间树、WAL 组提交、温度感知刷盘。
3. 为阶段性成果上传提供**可复现的测试证据**：命令、输出、退出码、检查计数、性能数据。

## 3. 测试分类与用例矩阵

### 3.1 单元测试层（storage_ut.exe）

对存储子系统内部机制做**确定性断言**，覆盖：

| 类别 | 覆盖点 |
|---|---|
| 页式存储 | 页分配/释放/读回、Page 复位、空闲页持久化（`.fpl` 重启复用/防活页误复用/旧库兼容/页数漂移丢弃） |
| 替换策略 | LRU / FIFO / CLOCK / LRU-K（含与 LRU 命中率对照）、命中统计、替换日志、环形上限 |
| 缓冲池 | 内存上限换算与统计、页级读写锁（防撕裂/多读并发）、后台刷脏、温度感知刷盘 |
| 磁盘 I/O | IO 读写计数、块设备故障注入（写失败/读失败/坏块 CRC 拦截）、页 CRC 校验 |
| 页内分配器 | first-fit 分配/合并/碎片统计/边界防御 |
| 日志与恢复 | WAL 记录、组提交 fsync 合并、undo/redo、CLR 链 |
| 并发与事务 | 多会话并发、死锁检测、隔离级别（RC/RR/SERIALIZABLE/SNAPSHOT）、谓词锁、行锁升级、MVCC 版本链、FCW 冲突、二级索引快照扫描、乐观 B+Tree 分裂/扫描 |
| 优化机制 | 谓词区间树 O(log P)、快照低水位 O(1)、内联真空、索引墓碑回收、后台真空线程 |

### 3.2 端到端 SQL 回归层（sqlcompiler.exe + tests/sql）

53 条 SQL 脚本，覆盖指导书「CREATE TABLE / INSERT / SELECT(含 WHERE) / DELETE」核心操作及项目扩展：

| 类别 | 脚本示例 |
|---|---|
| 基础 DDL/DML/查询 | 00_smoke ~ 06_operators |
| 聚合/分组/排序/连接 | 09~15、17~20、32、38 |
| 约束/类型/函数/视图/UDF/触发器 | 12、16、26~31、33、42、44~47 |
| 索引 | 34_index_basic、35_index_lifecycle、36_index_scan |
| 事务/隔离 | 40_txn_view_udf、43_upsert、48_acid_undo、51_nested_savepoint、52_set_isolation |
| 崩溃恢复（两阶段） | 49_acid_recovery、50_undo_clr |

**判定规则**（与 `run_all_tests.bat` 一致）：退出码 0 且输出无 `sqlcompiler> Error:` 行即通过。

### 3.3 崩溃注入层（两阶段）

| 用例 | Phase 1 | Phase 2 预期 |
|---|---|---|
| 49_acid_recovery | CREATE+INSERT 基线、BEGIN、UPDATE 未提交、`\crash`（期望退出码非 0） | 重启后未提交 UPDATE 回滚（bal=100）、已提交 UPDATE 持久（bal=60）、ROLLBACK 生效 |
| 50_undo_clr | CREATE+3 基线行、BEGIN、`\crash_after_undo_steps 1`、3 行 INSERT、ROLLBACK（期望退出码非 0） | 重启后仅 3 行，4/5/6 由 CLR 链补做全部 undo |

## 4. 测试执行步骤

### 步骤 1：构建
```powershell
cmake -S . -B build
cmake --build build --config Debug
```

### 步骤 2：存储单元测试
```powershell
Set-Location build
.\storage_ut.exe | Tee-Object ..\docs\test_evidence\storage_ut_run.log
# 预期：XX checks / 0 fails，exit 0
```

### 步骤 3：全量 SQL 回归（逐条脚本独立建库）
用 PowerShell 管道逐行喂入，逐脚本执行并判定退出码与错误行（详见执行记录文档 03）。

### 步骤 4：崩溃注入两阶段
复用 `tests\run_acid_recovery.bat` / `tests\run_acid_clr.bat` 的脚本逻辑（在 PowerShell 中复刻，避免 `cmd /c`），验证 Phase1 崩溃、Phase2 恢复语义。

### 步骤 5：可配行为抽查（\stats 与内存上限）
- `\stats` 命令输出缓冲池命中率、替换日志、IO 统计、内存占用、后台刷脏状态；
- `SQLCOMPILER_BUFFER_MEMORY=8192` 下缓冲池降为 2 帧。

## 5. 通过准则

1. storage_ut：**0 fails**（当前基线 58325 checks）；
2. SQL 回归：**55 passed / 0 failed**（53 条 SQL + 49/50 崩溃注入）；
3. 崩溃注入：Phase1 均非 0 退出（崩溃生效），Phase2 均 exit 0 且恢复语义正确；
4. 无死锁、无超时、无 flaky（并发用例多次复跑稳定）。

## 6. 风险与说明

| 风险 | 缓解 |
|---|---|
| SQL 回归中个别脚本为负面用例（如 42 CHECK 约束错误） | 判定规则已区分「预期错误」与「异常错误」：所有脚本 exit 0 即整体通过 |
| 崩溃注入依赖 `\crash` 命令使进程非 0 退出 | 在 PowerShell 中复刻 bat 逻辑，明确断言 phase1 退出码非 0 |
| 测试耗时（58325 checks + 53 条 SQL） | 测试在后台执行并记录完整日志，证据可复现 |
